# Training / Programs / Build a new long-term plan

Build a new long-term program through a resumable assessment/design/review workflow. The same conversational model performs the reasoning; this is not another agent or a fixed questionnaire.
First understand primary/secondary goals, priorities, start/end dates, events and success criteria. Read saved profile/preferences and the current program before asking for known details. Consider sport-specific recent volume/consistency, longer trends when relevant, intensity distribution, actual completed tolerance/feedback, recent recovery, coverage, interruptions, experience, equipment/terrain, sensors and confirmed FTP/HR, restrictions, realistic weekly availability, work/travel, existing commitments and the desired mix of sports. Retrieve summaries first and inspect source activities only when necessary. Related nutrition evidence is relevant only when it affects the plan; don't automatically load nutrition skills.
Use update_task to retain a planning brief, decisions, assumptions, evidence dates, selected record IDs, draft block structure, current stage and unresolved questions. Save planning state before an expensive preview. Returning later must continue the draft rather than repeat intake. Separate recorded facts, explicit decisions and provisional assumptions. Refresh time-sensitive evidence before final review if necessary.
Stages: establish brief; assess baseline; design phases/blocks and sport roles; make a practical weekly structure and initial session horizon; explain tradeoffs and review; present a ready preview for existing approval/activation; retain review criteria for later progress assessment. Stages do not require separate confirmations or one model call each. Do not generate every detailed workout months ahead when block direction plus an initial horizon is sufficient.
preview_training_plan accepts a structured brief and candidate_answers. Supply retained fields explicitly rather than depending on free-text extraction. Read returned questions, calibration_questions, strength_questions, status and limitations; they are evidence to interpret, not canned prose to repeat. get_training_context contains preferences, not activity history. Explain why a missing field matters, and ask only essentials. Updating setup is a separate reviewable proposal, never a prerequisite to discussing the draft.
Preserve completed history, existing commitments and secondary sports unless explicitly changed. A replacement plan must identify the existing root plan ID. A preview is not activation; present its review action. Publication is a separate requested operation. Long-term planning can use a larger measured reasoning/context budget than a session edit. Do not initiate automatic future reviews or background actions.

Read relevant saved training notes before planning. They are concise user preferences, scoped by activity and workout type; a specific workout type overrides activity-wide defaults. For an explicitly recurring instruction, read its note revision then use save_training_note to replace the same topic. Keep one clear sentence, at most 160 characters, without chat history or repetition. Supply sets/rest_seconds/continuous_endurance settings when explicitly requested; keep the text consistent with those settings. A one-day change remains a session edit. A note save alone does not change existing workouts or confirm Garmin publication.
