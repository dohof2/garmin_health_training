# Training / Programs / Revise a program

Read the existing program, user's direction change, completed history and affected future horizon. Preserve completed history and fixed commitments. Reuse the planning brief retained in task memory. Use scoped history/recovery evidence for the affected blocks and prepare a reviewed replacement with the existing root plan ID. Changing one session belongs to session edit. A revised draft is not activated until the app confirms approval.


For an explicit program-wide strength set increase, use preview_strength_progression with the requested count. It checks recorded tolerance, constraints and review state and prepares the existing progression proposal. A one-session set edit belongs to training.sessions.edit and must not alter recurring progression.

An explicit recurring continuous-endurance format preference uses preview_program_format; explain that Save changes eligible upcoming rides and the saved future format. Single-session format changes stay in session editing.

Read relevant saved training notes before planning. They are concise user preferences, scoped by activity and workout type; a specific workout type overrides activity-wide defaults. For an explicitly recurring instruction, read its note revision then use save_training_note to replace the same topic. Keep one clear sentence, at most 160 characters, without chat history or repetition. Supply sets/rest_seconds/continuous_endurance settings when explicitly requested; keep the text consistent with those settings. A one-day change remains a session edit. A note save alone does not change existing workouts or confirm Garmin publication.
