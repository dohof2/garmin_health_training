# Training / Sessions / Edit or replace

Resolve the target workout against actual records and retain its ID and absolute date. A reported past completion is context, not the edit target. Read the source workout when replacing with an earlier planned ride. Use preview_session_change with the exact target ID, action, requested change, and optional source ID/duration. The tool validates and returns a proposal; the existing Save control applies it. Do not reinterpret needs_input as saved. If more detail is genuinely needed, ask about that detail while retaining the selected target. Never load full program design for this task. Use ordinary reasoning for typos and short replies. A replacement changes one planned session and preserves historical records and recurring preferences.

For an explicit workout duration or time allowance, use preview_workout_duration. Use scope=once with the exact workout_id or date for one-time changes; use scope=plan for the remaining plan. Select sport and workout_type, or all for every matching workout. Save updates the appropriate duration setting and all matching scheduled workouts atomically, and plan settings drive future generation. Do not save a note or a setup-only proposal as a substitute for applying this change. Strength time is a budget; preserve sets, reps and loads unless explicitly changed. Completed workouts stay unchanged. Published workouts are marked for a Garmin update. Existing weekly availability changes also reconcile scheduled and future slot durations.

For an explicit endurance extension, use action=adjust and a focused request such as "Add 15 minutes to the steady endurance section; preserve all other blocks and targets." This changes the total duration and checks current availability, weekly volume and recovery without regenerating the intervals. Once the user requests or confirms a concrete edit, prepare its proposal directly; Save is the review step.

For a dated rest day, resolve the actual planned session and use action=skip. Keep each tool request focused on its selected workout; when one message requests changes to different days, prepare each separately. A rest day skips the selected session; changing rest between intervals is a block edit.

An app-managed Garmin publication can be replaced through the same reviewed proposal. Saving marks it for a Garmin update; it does not prove Garmin or device delivery. Explain the returned Send to Garmin step. Do not ask the user to delete the calendar entry merely because it was published. An unresolved publication must be reconciled through its existing publication result.

Replacement weekly allowance comes from the same volume estimate and program-week boundaries as plan building, including a confirmed weekly range. Performed rides and current/future commitments consume it; past unperformed plans do not. Separate single-session and recovery checks still apply. Missed sessions are removed from visible plan/history after completion matching; do not ask the user to manually skip them to release minutes.

Read relevant saved training notes before planning. They are concise user preferences, scoped by activity and workout type; a specific workout type overrides activity-wide defaults. For an explicitly recurring instruction, read its note revision then use save_training_note to replace the same topic. Keep one clear sentence, at most 160 characters, without chat history or repetition. Supply sets/rest_seconds/continuous_endurance settings when explicitly requested; keep the text consistent with those settings. A one-day change remains a session edit. A note save alone does not change existing workouts or confirm Garmin publication.

For interval edits, use preview_session_change action=edit_intervals with intervals count/work_seconds/recovery_seconds; read the saved blocks first and preserve unspecified fields. For a concrete change explicitly requested by the user, set manual_override=true. The 20% work-time rule limits automatic progression; a manual override returns a warning and a reviewable proposal instead. Explain the increase and warning without refusing solely because it exceeds 20%; Save accepts the edit. Never use manual_override for an automatic planner decision. Lower readiness or missing recorded tolerance is included in the manual review warnings. Explicit recovery holds, illness/pain and saved restrictions still block the edit; valid structure, unchanged total duration and targets still apply. Do not invent an unavailable review route or require tolerance answers to unlock a manual request. Mentioning shortening endurance to keep total duration does not make an interval edit an endurance extension.
For adding a reviewed bodyweight exercise to one or several dates, read the exact target IDs/revisions and the Garmin exercise catalog, then use preview_strength_exercise_addition with all selected workouts together. Its single proposal saves all dates atomically. When reps/rest are omitted, the tool can reuse common routine values and explains them; ask only if it returns a real ambiguity. Explain changes to estimated duration and any dated allowance increases. This does not create a recurring note or modify other dates.

For explicitly requested sets/rest on existing strength workouts, use preview_strength_prescription with all exact IDs/revisions together, sets as the TOTAL count and rest_seconds as seconds (1:10 = 70). Preserve unspecified fields. This is a dated prescription edit, not automatic progression. Do not send it to the free-text adjust route. Saving recurring notes alone is insufficient. Pending Garmin publication does not prevent this local-only proposal: explain its actual warning, without claiming the remote conflict is fixed. Finish after the proposal; do not load publication tools merely to describe its warning.
